# Domain docs

Use a single-context layout with GLOSSARY.md at the repo root
and architectural decision records under docs/adr/.

Before exploring, read the glossary and ADRs relevant to the work.
If they do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

Use the glossary's vocabulary in issues, proposals and tests.
Flag any conflict with an existing ADR and explain the reason.

If GLOSSARY-MAP.md is introduced later, follow its pointers to
the relevant context glossaries and ADRs.
